System Architecture & Engineering Decisions

Deep dive into the architectural principles powering Kanban Studio's performance, stability, and AI integration.

Frontend: Next.js 15 SSG Export Target

Single-Container Static Export: Next.js is configured with output: 'export' in next.config.ts. The build produces plain HTML, JS, and CSS files in /srv/static, which FastAPI serves directly.

  • Zero Node.js runtime memory overhead in production container.
  • @dnd-kit PointerSensor with 6px drag activation threshold.
  • Namespaced DnD IDs (c{id} and d{id}) preventing ID conflicts.
  • Optimistic React state updates with zero-latency drag updates.
Backend: FastAPI Sync Threadpool anyio Threadpool

Non-Blocking Threadpool Handlers: Route handlers are declared using standard def (synchronous), executing in FastAPI's background anyio worker threads. This isolates blocking SQLite disk I/O without blocking the asyncio loop.

  • SQLAlchemy 2.0 Declarative Mapped models.
  • Explicit selectinload eager loading preventing DetachedInstanceError.
  • PBKDF2-SHA256 password hashing with 600,000 iterations.
  • In-memory bearer session store mapping tokens to users.
Database: SQLite + Foreign Keys PRAGMA Hook

Relational SQLite Integrity: SQLite stores data in /data/kanban.db. An engine connection event listener executes PRAGMA foreign_keys=ON on every connect.

  • Alembic migration pipeline resolving schema updates.
  • Sequential positional re-indexing (0, 1, 2...) for cards & columns.
  • Cascading deletes (ON DELETE CASCADE) on parent records.
  • Zero-configuration file persistence.

Complete Function Engine Reference

Signatures, execution logic, and module origins for core functions.

load_board(db, board_id, user_id) backend/app/kanban.py

Fetches board by ID using SQLAlchemy. Verifies that board user_id matches requesting user. Raises HTTP 404 if missing or HTTP 403 if unauthorized.

move_card(db, card, target_column_id, position) backend/app/kanban.py

Re-calculates card array order in source and target columns. Re-indexes card positions sequentially (0, 1, 2...) to ensure zero index gaps across columns.

chat_with_board(board, question, history) backend/app/services/ai.py

Formats system prompt, board JSON snapshot, and conversation history. Invokes OpenRouter API (`openai/gpt-oss-120b`) and parses JSON reply containing conversational text and board operations.

apply_operations(db, operations, user, board_id) backend/app/services/board_ops.py

Executes AI proposed operations (add, edit, move, delete) transactionally. Validates user ownership and input bounds, returning applied and skipped logs.

hash_password(password) backend/app/security.py

Generates a 16-byte random salt and computes a PBKDF2-SHA256 digest with 600,000 iterations. Returns formatted string pbkdf2_sha256$600000$salt$digest.

moveCard(columns, activeDndId, overDndId) frontend/src/lib/kanban.ts

Parses namespaced DnD IDs (c{id}, d{id}), isolates dragging card, removes it from source column, and inserts it at destination target position for instant optimistic UI updates.

End-to-End System Workflows

Visual step-by-step breakdown of core user and AI interactions.

1. Drag-and-Drop Card Movement Execution

1
Sensor Activation
User drags a card. @dnd-kit PointerSensor checks distance constraint (6px). DragOverlay renders float preview card.
2
Optimistic UI Update
onDragEnd event fires. moveCard() in lib/kanban.ts updates local React state immediately for 0ms visual latency.
3
Backend API Sync
Frontend issues PATCH /api/cards/{card_id} with target column_id and position.
4
Database Transaction & Re-indexing
Backend move_card() executes inside a SQLite transaction, re-indexing cards sequentially. If request fails, frontend state reverts.

2. AI Assistant Natural Language Mutation

1
Chat Prompt Submission
User inputs "Add a High priority bug fix task to In Progress" in ChatSidebar.
2
Context Snapshot & LLM Call
FastAPI POST /api/ai/chat builds board snapshot JSON and calls OpenRouter API (openai/gpt-oss-120b).
3
Transactional Mutation
board_ops.apply_operations() parses operations, executes DB mutations, appends chat message, and returns updated board tree.
