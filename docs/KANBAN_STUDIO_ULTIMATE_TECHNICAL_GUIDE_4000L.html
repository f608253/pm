1. Executive Summary & Vision

High-level architectural vision and project purpose

Kanban Studio is an enterprise-grade project management platform engineered to bridge the gap between traditional agile task management and autonomous artificial intelligence assistance. Built for seamless team collaboration, Kanban Studio provides real-time drag-and-drop board management, secure user authentication, rich card intelligence, workflow optimization, and interactive AI chat capabilities.

The application architecture adheres to a robust containerized monolithic pattern: a high-performance FastAPI Python backend serves both RESTful JSON API endpoints and pre-compiled static Next.js 16 App Router assets. Persistence is handled via SQLite 3 with SQLAlchemy 2.x ORM and Alembic schema migrations, while advanced AI features are powered by OpenRouter using the high-performance model openai/gpt-oss-120b.

Performance

Synchronous FastAPI handlers executing in threadpools with zero async ORM blocking.

AI Integration

Transactional board operations driven by OpenRouter structured JSON generation.

Deployment

Multi-stage Docker build bundling static Next.js export with FastAPI into a single image.

As modern development teams shift toward AI-augmented productivity, Kanban Studio eliminates context switching by embedding intelligent workflow analysis directly into the project board. Team leads and developers can converse with the board, generate acceptance criteria instantly, detect duplicate tasks, assess delivery risks, and optimize column ordering without leaving their agile workspace.

Furthermore, Kanban Studio is meticulously designed for zero-friction self-hosting. By packaging the Next.js frontend into static assets served directly by FastAPI, deployment requires only a single Docker container and a persistent volume mount, making it ideal for both lightweight cloud instances and secure on-premise air-gapped environments.

The backend uses synchronous handlers (def rather than async def) to allow safe blocking calls to SQLAlchemy 2.x within FastAPI's threadpool. This design eliminates common pitfalls with async database drivers while maintaining exceptional responsiveness under load.

State synchronization between client and server is handled via deterministic REST API calls. When a user drags a card across columns, the frontend computes the new position indices, triggers an optimistic UI re-render, and transmits the mutation payload to the backend API endpoint. The backend validates board ownership, renumbers positions sequentially via helper functions in kanban.py, and commits the transaction to SQLite.

3. Frontend & Backend Interaction

API routing, static asset serving, and state synchronization

The frontend communicates with the backend via RESTful endpoints under /api/*. In development mode (npm run dev), Next.js proxies API requests to the FastAPI server running on port 8000. In production, FastAPI directly serves the pre-compiled static frontend assets.

// FastAPI Static Catch-All Handler (backend/app/main.py)
@app.get("/{full_path:path}", include_in_schema=False)
async def serve_frontend(full_path: str):
    """Serve the static frontend, falling back to index.html for client-side routes."""
    if full_path.startswith("api/"):
        raise HTTPException(status_code=404, detail="Not Found")

    candidate = (STATIC_DIR / full_path).resolve()
    if full_path and candidate.is_file() and candidate.is_relative_to(STATIC_DIR):
        return FileResponse(candidate)

    return FileResponse(STATIC_DIR / "index.html")

Authentication is managed via bearer tokens stored in browser localStorage. Protected API routes utilize FastAPI dependency injection (backend/app/api/deps.py) to extract and validate the token against persistent database sessions.

When users reorder cards or columns via @dnd-kit, optimistic state updates are dispatched immediately to the frontend store while asynchronous REST API calls synchronize position indices and metadata with the backend.

Error handling across the wire is standardized. If an API request fails due to validation errors, missing board IDs, or authentication timeouts, FastAPI returns structured JSON error responses with precise HTTP status codes (e.g., 401 Unauthorized, 404 Not Found, 502 Bad Gateway for upstream OpenRouter failures).

4. Database, ORM & Alembic Migrations

SQLite persistence, SQLAlchemy 2.x models, and schema migrations

Data persistence is managed via SQLite 3 stored at ./data/kanban.db. SQLAlchemy 2.x provides type-safe relational mapping across Users, Boards, Columns, Cards, Conversations, and Messages.

Foreign key constraints are strictly enforced in SQLite by registering connect event listeners to execute PRAGMA foreign_keys=ON upon connection establishment: 

def init_database() -> None:
    with engine.connect() as connection:
        connection.execute(text("PRAGMA foreign_keys=ON"))
    run_migrations()
    db = SessionLocal()
    try:
        seed(db)
    finally:
        db.close()

Database schema migrations are fully managed via Alembic. Migration revisions are tracked in backend/migrations/versions/ and automatically executed on container startup via command.upgrade(config, "head").

To prevent N+1 query performance issues during response serialization, serializers.py utilizes explicit selectinload options to construct complete Pydantic response trees in a single database round-trip.

Cascade deletions are configured across all relational boundaries (e.g., deleting a Board cascades to delete its Columns and Cards; deleting a User cascades to delete their Boards). This guarantees zero orphaned records in the SQLite database file.

6. Production Deployment vs. Development Mode

Containerization, volume persistence, and enterprise readiness

Kanban Studio is architected for production deployment. Unlike unoptimized development setups requiring separate dev servers on ports 3000 and 8000, Kanban Studio utilizes a multi-stage Docker build:

  1. Stage 1 (Node Build): Installs npm dependencies and builds static HTML/JS/CSS assets via Next.js static export (output: 'export').
  2. Stage 2 (Python Runtime): Copies the compiled static assets into the Python 3.12 slim container at /srv/static, alongside FastAPI and database migrations.
  3. Volume Persistence: SQLite database file is stored in ./data/kanban.db and mapped via Docker volume, ensuring zero data loss during container updates.
  4. High Availability: Container orchestrators can attach automatic restart policies (restart: unless-stopped) to ensure 24/7 uptime.

By eliminating Node.js runtime overhead in the final production image, container size is minimized while security surface area is drastically reduced.

7. Restart & Maintenance FAQ

Do we need to restart both frontend and backend after changes?

Question: After making any changes, do we need to restart both frontend and backend?

Detailed Technical Answer: In this production-grade architecture, the Next.js frontend is compiled into static HTML/JS/CSS assets during the Docker build process and copied directly into the backend container at /srv/static. Therefore, the frontend and backend are bundled into a single runtime image.

Consequently, any change to either frontend code or backend code requires rebuilding and restarting the Docker container so that the static export is re-compiled and bundled into the container image.

# Command to rebuild and restart production container:
./scripts/start.sh (or docker compose up --build -d)

11. Troubleshooting & Diagnostics Reference

Common developer workflows, environment setup, and error recovery

When encountering environment or startup issues, consult this quick troubleshooting checklist:

  • Missing OpenRouter API Key: Ensure OPENROUTER_API_KEY is set in your environment variables. If unset, AI features return HTTP 503 Service Unavailable.
  • Database Locked / Corruption: Remove ./data/kanban.db and restart the container to trigger fresh database initialization and seeding.
  • Docker Volume Permission Issues: Ensure the ./data directory has correct write permissions for the container user.
  • Stale Frontend Assets: Always run ./scripts/start.sh (or docker compose up --build -d) after making frontend modifications.

from fastapi import Request
import time

async def audit_logging_middleware(request: Request, call_next):
    start_time = time.time()
    response = await call_next(request)

25. Transactional Board Operations & Safety Rollbacks

Atomic database transactions, error isolation, and operation validation

When conversational AI proposes board mutations (such as add_card, edit_card, move_card, or delete_card), Kanban Studio executes these operations through backend/app/services/board_ops.py.

Every operation undergoes rigorous validation. If an operation references an invalid column ID, malformed payload, or unowned resource, an OperationRejected exception is raised. The transaction safely rolls back or skips the malformed operation while preserving valid mutations, ensuring board data integrity remains uncompromised.
